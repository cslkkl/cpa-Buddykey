# 决策：账号范围用「串行切换启用集合」实现（2026-11-12）

状态：生效

## 问题

需要「每把 key 只能落到指定的几个账号」。CPA 侧要能按请求指定账号，才谈得上干净的实现。

## 决策

请求前把 CPA 的全局启用集合调成本 key 的范围，请求结束在 `finally` 里还原；
范围请求用一把互斥锁串行。

## 替代方案（强制）

- **给每把 key 配一个独立 CPA 实例**：隔离性好，但每个实例要重复加载 8 个号的凭据与插件，
  内存与端口成本翻倍，个人机器上不划算。
- **按 key 绑定 `access.api-keys`**：不可行 —— 那条配置只是裸字符串列表，
  路由只有 `round-robin` / `fill-first` / 权重排除（核对 `config.example.yaml` 的
  access 与 routing 两段），没有 per-key credential binding。
- **用 `weight` 排除账号**：同样是全局的，且要开 `weighted-round-robin`，
  改的是整个池子的调度策略，代价比切换启用集合更大。
- **绕过 CPA 直连上游**：需要复刻 header、模型映射、流式协议，风险与维护成本都高，
  且会让「登录态由 CPA 管」这条既有优势消失。

## 影响

- 并发不同范围的 key 会排队；同一时刻只有一个范围生效。
- 切换窗口内其他客户端可能看到被改动的启用集合。
- 换来的是：不复制上游协议、不新增进程、改动只落在本服务与 CPA 的既有接口上。
