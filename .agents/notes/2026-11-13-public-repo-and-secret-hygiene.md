# 决策：仓库保持公开，靠脚本而非人工记住来防密钥泄露（2026-11-13）

状态：生效

## 问题

这个项目的目的就是「别人拉下来就能用」，所以仓库必须**公开**。
但它管的恰好是一堆敏感东西：上游 API key、管理口令、账号 OAuth 登录态。
公开与敏感放在一起，唯一的风险是「某次误把密钥提交上去」。

两个具体问题需要定下来：

1. 公开还是私有？
2. 「不把密钥交上去」这条靠什么保证？

## 决策

**仓库保持公开。**

**靠三道机制防泄露，不靠记忆：**

- `.gitignore` 排除 `data/`、`runtime/`、`bin/`；
- `tools/check-secrets.mjs` 扫「被跟踪的敏感路径」与「内容里的真密钥形状」，
  接进 `npm run check`（手动那道）；
- `npm run hooks:install` 装 pre-commit 钩子，在 `git commit` 那一刻再拦一次（真拦住那道）。

**「公开」与「别人能用我的服务」是两件事**，必须分开看：

- 公开仓库 = 别人能看到「怎么做这个东西」，可以自己搭一套；
- 自己的服务 = 一个具体地址 + 一道管理口令，与仓库无关。

账号、额度、口令、登录态全部在服务器的 `~/.cli-proxy-api` 与 `data/` 里，从不进 git。

## 替代方案（强制）

- **设为私有**：直接否掉项目存在的意义 —— 别人拉不到代码，「拉下来就能用」不成立。
  之前临时设公开只是为了让用户的服务器能匿名 clone，装完就该维持公开。
- **公开但只靠「记得别提交」**：实测不可靠。密钥泄露只需要一次疏忽，
  而 `git add -f` 能绕过 `.gitignore` —— 没有任何机制阻止它。
- **公开 + 只跑 `npm run check`**：不够。那是**手动**的，忘记跑就漏过去；
  且泄露发生在 `git commit` 那一刻，检查应该拦在那里。
- **用 git filter-repo / BFG 事后清理**：来不及。别人可能已经 fork 或缓存，
  历史改写不影响已扩散的副本 —— 所以只能事前拦。

## 影响

- 新使用者需要跑一次 `npm run hooks:install`（`.git/hooks/` 不受版本控制，
  没法让 clone 下来就自带）。
- 检查脚本**只认密钥的真货形状**（如 `sk-pool-` + 32 位十六进制），不猜占位符写法。
  这是刻意的：如果把「文档里写 `sk-pool-你的key`」也判成泄露，检查会被关掉，
  比没有检查更糟。
- 一旦真的提交过，处置方式只有一个：**立刻作废那个密钥并重建**。
  删文件、改历史都不算处理。
